# MATACS-TH-2026-02: Technical Design

**Scope.** Human-supervised triage of proposals for a 150 kW commercial rooftop solar project in Windsor, Ontario. The available project summary sets a CAD $260,000 ceiling, a 16-week completion limit, and mandatory bidder-held Ontario electrical contractor licensing, WSIB clearance, and CAD $5 million liability insurance. The complete brief and source PDFs were not supplied in the repository; proposal facts and scores below therefore remain subject to source-document verification.

## 1. AI vs. rules

Admins create versioned criteria in category-specific screens. Each criterion has a stable ID, type (mandatory or weighted), value/rule, weight where relevant, effective version, and change history. No category criterion is hard-coded. Reviewers upload PDF files and select the category. File validation rejects unsupported, encrypted, oversized, malformed, or malware-positive files; safe text extraction/OCR preserves page references.

AI is limited to extracting requested facts into a strict evidence schema, identifying contradictions/uncertainty, and flagging embedded instructions. Proposal content is untrusted data, not prompt authority. AI never decides eligibility, awards points, or selects a winner. Deterministic application code validates model output and evidence references, checks mandatory and project limits, calculates scores, orders eligible bids, and produces reasons. Human reviewers inspect source evidence, resolve flags, approve outcomes, or record reasoned overrides.

## 2. Consistency and explainability

Each decision uses a frozen criteria version, weight set, formula version, validated fact set, and recorded model/prompt version. Proposed weights are experience 30%, price 25%, timeline 15%, warranty 15%, and team/approach 15%; admin validation requires each weight to be nonnegative and total exactly 100% (using decimal arithmetic). For a fully evidenced, eligible proposal, total = `0.30E + 0.25P + 0.15T + 0.15W + 0.15A`, rounded only once to two decimal places. Store unrounded component values too.

Proposed explicit normalizations, pending admin confirmation against the full brief: price score `P = 100 * (1 - price / 260000)`, clamped to [0,100]; price above the hard ceiling fails the project constraint. Timeline score `T = 100 * (1 - weeks / 16)`, clamped to [0,100]; over 16 weeks fails the project constraint. Experience score `E = min(100, 100 * qualifying_similar_projects / 5)`, where a qualifying project is a source-documented commercial rooftop PV installation of at least 150 kW completed in the preceding 10 years; the five-project saturation point and definition are proposed rubric parameters requiring admin approval. Warranty score `W = 50 * min(panel_years / 25, 1) + 50 * min(workmanship_years / 10, 1)`; the 25/10-year reference levels are proposed rubric parameters, not inferred requirements. Team/approach score `A = 20 * (named project manager + certified crew + project-specific safety plan + roof-load assessment + monitoring of at least 12 months)`, with each term 1 for confirmed evidence, 0 for explicitly confirmed absence, and unresolved for missing, contradictory, or uncertain evidence. All numeric inputs must be nonnegative and source-backed; missing, contradictory, or uncertain inputs block final scoring rather than silently becoming zero. A numeric result is reproducible from the recorded facts and rules.

Mandatory eligibility requires the bidder itself to hold and state the Ontario electrical contractor licence, confirmed WSIB clearance, and at least CAD $5 million liability insurance. Subcontractor credentials do not satisfy the bidder requirement. The stated budget and 16-week project constraints are hard gates as well as within-limit score anchors. Failure is ineligible; incomplete or conflicting evidence is flagged pending human resolution. Only fully eligible proposals with all weighted inputs reliably established are ranked. Exact score ties use lower price, then shorter completion, then proposal ID as deterministic tie-breakers. Unresolved proposals receive null rank and score; no false precision is used.

## 3. Human in the loop

Reviewers see criterion-by-criterion evidence snippets and page citations alongside source pages, extracted values, confidence/uncertainty, and flags. They may confirm, correct, or mark a fact unresolved; every change records actor, timestamp, old/new value, reason, and source evidence. Authorized approvers accept the ranked output or override eligibility, score, or order with a required rationale and supporting evidence. The system records uploads and file hashes, criteria versions, AI model and prompt versions, raw/validated output, validation errors, scores, ranks, flags, approvals, overrides, and final decision. Access is role-based and audit records are append-only.

## 4. Changing criteria

Editing criteria creates a new immutable version; it never rewrites an earlier evaluation. Admins validate weights and rules, preview effects against a test set, obtain approval, and set an effective date. New evaluations use the new version. Existing evaluations retain their original version and remain reproducible. If policy requires rescoring, create a clearly labelled new evaluation for every proposal in the cohort, retain the old results, and notify reviewers; never compare scores from different versions as though equivalent.

## 5. Risks

Extraction errors are limited by page-level evidence, schema validation, deterministic range/type checks, and human confirmation. The model must abstain on absent facts; evidence-free assertions cannot pass criteria. Criteria and formulas are visible, versioned, and applied equally; admins review outcomes for disparate effects and rubric drift. Prompt injection is addressed by treating PDF/OCR content as untrusted, isolating extraction from tools/actions, recording injection attempts, and ignoring them as instructions without penalizing unrelated merits. Missing and contradictory facts trigger flags and null scores/ranks, not optimistic assumptions. File scanning, least-privilege access, encryption, retention limits, and minimal data sent to the model reduce security and privacy exposure. Model calls use per-file size/page limits, deduplication, bounded retries, and human review for repeated failures to control cost. AI output is advisory; a human remains accountable for the procurement decision.
